# 超级智能体上下文约定

状态快照、用户请求与证据分开传递。减少模型每轮读取的重复信息，同时保留原始任务、工具调用与结果、检查点和汇报以供恢复。

## 状态快照

宿主通过类型化 `hostContext` 传递版本、节点身份及当前状态，不写入用户正文。Pi 保存独立的 `tokenbird.super-agent-context.v1` 消息；每次模型请求仅投影最新快照，原始会话记录保持完整。压缩输入也按可信类型去重，用户输入中的同名 XML 标签属于普通正文。压缩后恢复本轮固定快照，不拆散工具调用和结果。其他 SDK 暂无请求投影接口，接收同样经过裁剪的尾部状态，由其原生压缩管理历史；不会强制重建会话。

动态团队工作节点只自动获得当前任务、对应需求、最近三步检查点和下一步、依赖与产物引用、待核实操作标识、显式引用的板项及实际环境。资源目录只提供数量和发现工具，完整检查点按引用读取。V2 主节点只获得工作数量及后台规划定向汇报；后台规划获得需求原文引用、目标和计划摘要、协调节点阶段汇报；派工协调获得当前计划版本、执行状态、模型目录及自己子节点的汇报。用户原文与附件引用在 requests 中只保存一份，后台按 ID 无损读取；各跳只传计划或证据引用。模型目录仍保留所有启用模型的 ID，完整选型说明可从设置查询。

旧版固定团队保留其已有的资源目录和状态入口，避免引用其角色工具集中尚未提供的查询路由；类型化 Pi 快照及技能正文改为引用同样适用。

V2 的 peers 默认只列当前活跃节点、本轮固定汇报的作者、发送方及明确引用的节点。历史执行节点仍通过工作列表的精确任务详情查询，不把全部已结束的工作节点重复注入每一轮上下文；查询不改变父子归属和通信拓扑。任务摘要包含 `completed` 完成标记和排队 `blocker`；健康查询还列出占用资源的任务及未决操作 ID。

## Skills

节点提示词只注入技能名称、用途、路径及内容版本，不嵌入技能正文。默认协作技能拆为通用入口及交互、编排、执行、恢复参考文件。执行相关操作前读取适用内容，版本号不代表已经读取；压缩后缺少必要规则时重新读取。内置技能及包内参考的独立只读权限继续遵守 [权限约定](./permission-contract.md)，不会因按需读取产生权限死锁。

## 查询与证据

`super_agent_resource_catalog`、`super_agent_work_list`、`super_agent_reports` 和超级智能体的 `collaboration_board` 默认返回摘要，默认每页 20 条、最多 100 条；序列化内容预算默认 8,000 字符、最多 16,000 字符（含转义和响应元数据会有额外开销）。`nextOffset` 表示下一页，不得跳过宽记录。摘要提供 `complete`、`truncated` 和 `detailRef`，不能当作完整替换内容。

只在需要缺失事实时读取 `id` + `view=detail`，工作列表还需指定 `area`。长详情按 JSON 字符片段返回；从 `contentOffset=0` 开始，跟随 `nextContentOffset`，后续请求传入第一页 `hash` 作为 `expectedHash`，拼接完成后再解析 JSON。哈希变化时从第一页重读，不拼接不同版本。原始长文本、Unicode、路径、检查点和操作回执均保持可检索，不以摘要覆盖存储。

每个管理节点的定向通知 `reportBatch` 固定 `(afterSequence, throughSequence]`，新汇报留给下次；每个收件节点独立使用 reportCursors/eventCursors，固定本轮范围；成功完成后才推进该节点游标，失败重试不消费。主节点还须成功调用 super_agent_deliver，可用空回复静默消费。普通进度只唤醒派工协调，后台规划只处理新需求、计划问题和协调阶段报告；主节点只处理用户输入与后台交接。默认隐藏同作者、任务、需求版本及种类内被更新汇报替代的旧版本；问题不会被普通进度掩盖。按 ID 或 `includeSuperseded` 可追溯原文。批次中 `complete=true` 的短汇报无需再次读取。

## 轮次收尾与空响应恢复

对用户静默与模型轮次收尾分开处理。主节点无新增内容时通过 `super_agent_deliver(reply="")` 显式消费当前通知批次；所有节点仍应输出一次简洁的非空最终答复，不能仅留下思考、commentary 或工具调用。内部最终答复不会自动变成用户交付或目标验收。

后台规划和派工协调在没有新增可行动事项或有用汇报时，可以单独调用 `super_agent_finish_turn(note)` 显式结束内部轮次。其当前有效回执可恢复缺失的最终答复，并消费已处理的固定通知批次；不发送用户消息，不完成业务任务或目标，不核销未知操作。主节点仍使用 `super_agent_deliver`，执行子节点仍提交任务结果。完全相同、同版本、同证据引用的管理汇报复用已有报告，不重复唤醒上层；本轮显式复用回执仅可静默收尾，历史报告正文不能变成新的任务结果。

模型正常结束却缺少最终答复时，宿主可使用当前尝试中最后提交的有效交付回执（含空回复）、对应最终报告，或资源加载续跑回执恢复轮次。普通查询、派工、进度报告和历史会话答复不能替代最终结果。后续工具调用或新一次恢复会清除该尝试的收尾回执标记；待执行工具、未知操作结果、拒绝或部分应用回执及真实连接、鉴权、取消错误不能被这些回执覆盖。阶段报告不会被升级为任务完成或目标验收。

缺少收尾且无有效回执时仍保留原任务、会话和已生效动作，最多自动续跑三次；恢复提示要求先核对证据，只补缺失收尾与未完成步骤，不重放已完成动作。会话层把空响应事件交给超级智能体统一判定和恢复，避免在有效静默消费前发布合成红色错误；普通聊天仍保留空响应错误和重试入口。

自动空闲巡检保存语义进度指纹；用户输入、目标、计划、任务、产物、操作、共享板、脚本或环境没有变化时，不再定时重复启动同一检查，也不重新获得空响应重试预算。该指纹跨重启保留。新通知继续按收件箱处理，用户手动检查可以立即重查；外部状态变化若未进入宿主状态，需要显式检查或通过已有任务、脚本上报。

对应回归：`SuperAgentTerminalReceipt.test.ts`、`SuperAgentEmptyResponse.test.ts`、`SuperAgentTextRecovery.test.ts`、`SuperAgentTopology.test.ts`、`session-completion-workflow.test.ts`。

## 回归与观测指标

`host-context.test.ts` 通过真实 SDK 的 20 轮离线请求检查投影与原始历史；`SuperAgentContext.test.ts` 检查目录裁剪、100 步检查点恢复、Unicode 无损分页、版本变化与汇报替代范围。任务目录中的 `context-diagnostics.jsonl` 记录每轮上下文及消息字符数；Pi 工具诊断记录移除的快照数量和字符数。诊断不记录正文，写入失败不影响执行。

字符数用于回归比较，不等同于供应商实际 token 用量。完全控制、权限申请、角色边界和执行环境遵守原有产品约定。
