# 共享板保留和恢复约定

共享板最多保留 1024 条活跃内容，写入另受 8 MiB UTF-8 序列化内容预算限制。提高条目数量不增加自动上下文注入或查询分页预算；界面默认显示 20 条，并支持搜索和继续显示。

宿主每 30 分钟扫描一次；新增内容达到 768 条或触及内容预算时，在原写入中执行一次清理并继续写入。清理随服务心跳自动执行，不依赖持续工作、自检或模型轮次；应用启动加载工作区后继续维护。用户也可在共享板中点击“清理旧内容”，但正常维护和异常恢复均不需要手动点击。清理只按确定条件归档：完全相同内容的旧副本、显式过期项、超过 48 小时且不再引用的旧项；最近 32 条普通内容保留。宿主为执行节点新建板项记录 taskId，长期约定可显式置顶。

清理保留当前任务和依赖输入、检查点等待的板项、未读汇报、待执行或失败恢复轮次、未决操作证据、仍在运行的作者及板项之间的引用链。置顶优先于到期；引用优先于时间和重复判定。旧记录没有生命周期字段也可直接读取，不迁移或重建用户团队。

清理前将完整原文、修订号、作者、任务归属及归档原因保存至工作区 `super-agent/history/board/`，同步归档文件成功后才移出活跃板。归档保留原始 ID，便于追溯，失败不删除旧记录。

异常流程：

1. 归档遇到暂时性 I/O 故障时，同一维护调用最多尝试三次；永久路径错误结束当前这组尝试。失败后持久保存 `boardMaintenance.issue`、恢复次数和下次时间，按 1、2、4、8、16 分钟退避，之后每 30 分钟继续自动检查，存储恢复后自动归档并清除异常。重启保留恢复进度；旧版本遗留的手动阻塞状态也自动接续。压力写入不得绕过退避或不断推迟下次重试。界面显示下次自动检查时间，手动立即重试只作为可选入口。其他任务继续执行，容量尚足时仍允许板项写入。
2. 清理后仍达到容量时，保留现有条目并拒绝这一笔新增，返回 `[board:capacity]`；当前编辑草稿不关闭。宿主每分钟自动复查，任务完成、引用解除、内容过期后自动释放可归档空间，不需要用户触发清理。不以删除引用或未决证据换取空间。满条目数时仍可更新原主题；超过内容预算的历史板项可通过缩小已有内容逐步恢复。自动恢复清理不重放已经返回失败的写入或其他业务操作。
3. 版本冲突保持原条目不变，返回最新 revision，要求读取并合并，不自动覆盖其他作者。
4. 只有新归档、维护状态变化才产生定向共享板事件；重复的同一阻碍不持续唤醒模型。恢复成功清除异常状态。

共享板异常处理不改变节点通信拓扑、权限弹窗、内置 Skill 独立读取或完全控制语义。
