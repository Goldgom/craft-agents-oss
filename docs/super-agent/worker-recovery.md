# 保留主要节点与协作状态的执行节点恢复

已接入超级智能体运行时。普通聊天、MCP 重载及整个服务维护的通用设计仍见 `../restart-recovery-design.md`。

## 恢复契约

- 宿主启动的既有 `restoreSuperAgents` 扫描读取所有已配置工作区，无需打开客户端页面。存在中断轮次或未完成执行任务时，建立持久恢复记录。
- 手动入口为 `recover-workers`，使用稳定 `requestId`。界面“恢复任务”重试同一未完成记录；相同已完成请求不重复重建。
- 主节点、规划节点、派工协调节点的身份、配置和健康会话保留。主要节点若正在执行，先停止该轮并以新会话从持久协作状态接续。
- 全部执行 worker 清除运行会话绑定，下一次派工创建新会话。逻辑节点身份继续用于历史任务、原操作及报告的归属；原会话不删除。
- 用户请求、目标版本、计划、任务、任务板版本、产物、报告、通信历史及收件游标保留。恢复不提升验收结果，不重建用户请求，不回滚文件，也不关闭被操作的桌面应用。

## 持久状态与顺序

`SuperAgentDocument.generation` 标识当前执行代次；`workerRecovery` 保存恢复 ID、来源修订、阶段、原因、旧会话、旧轮次、原失败轮次 ID、待接续任务、未知操作与重试预算。它随原文档通过同步 `commit.json` 和兼容 `state.json` 提交，不引入第二个派工器。

建立屏障前先将完整原文档独占写入 `super-agent/history/recovery/<recoveryId>.json` 并同步到磁盘；备份失败时不开始重建。备份保留主要节点和协作状态，供审计和人工恢复使用。

顺序为 `stopping → reconciling → ready`，清理失败进入 `blocked`。先提交屏障并退休旧轮次，再在工作区串行队列外停止旧模型进程、取消并等待准备操作，防止取消回调与持久队列互相等待。确认旧会话归属和停止状态后重建 worker 绑定，并核对私有日志、原会话及磁盘存档。

准备操作或旧模型仍活动时不派工。自动清理最多尝试 5 次，失败后间隔 5 秒，次数和下一次时间跨重启保留；用户明确重试可重置清理预算。既有模型请求恢复截止时间、空响应次数、节点调用频率和连接限额不会因 worker 重建而清零。任务最多保留 100 次执行尝试，达到上限要求审查，而不删除旧证据。

恢复中再次退出时继续同一恢复 ID 和代次。新旧记录均可读取，旧记录默认代次 0。显式停止、取消及最新目标/计划版本在派发前重新校验。关闭 `continuousWork` 不阻止被系统中断任务的接续；用户停止仍阻止自动执行。

## 接续与资源

同一 `taskId` 保留业务身份。`executionAttempts` 记录实际轮次 ID、代次、原会话、开始/结束时间和结果。恢复前的运行尝试标记中断；新会话从原检查点、已提交动作、产物及原操作摘要继续。缺少模型检查点时仍能根据持久任务与回执继续。

已完成任务不重跑；待验收结果继续保留。等待任务保留条件。原生只读尝试在确认旧执行停止后可结清为 `interrupted`，不宣称其成功；外部写入、点击、拖动、输入及来源不明的程序操作必须有证据才能结清。无法确认的操作继续占用其审计范围，未声明审计范围时保留原任务资源；其他独立任务可以继续。

受管脚本使用原停止句柄。宿主异常退出后无法确认身份的脚本保持 `untracked`，阻塞其相关任务；不会仅凭 PID、时间或安静状态认定进程已结束。

旧会话不能派发新操作或提交新轮次。匹配原操作会话、调用 ID、工具身份及已存结果哈希的迟到回执可以归档并对账；不能覆盖新任务尝试。待核验任务在证据结清后自动重新入队，保留原任务身份。用户取消则禁止重新入队。

## 通信与回执兼容

主要节点被中断的轮次保留已提交 `toolCalls`、收件批次上下界和处理游标，新的模型上下文不得重复提交已完成动作。执行节点未处理的消息轮次（包括核验后的结果登记）交给新会话继续；相同消息只保留一个队列身份。用户可见交付沿用原持久协作回执。

恢复记录中的轮次继续保留通信链预算；恢复期间暂停通知补发和内部核验派工，为待接续轮次预留队列名额。脚本结果复核保留原通知身份及已提交动作，恢复投递计入原次数上限，避免重复通知或通过重启清空预算。

Pi 对 Bash 读取的分类只修改显示名称，开始与结束事件保持 Bash 身份及实际参数。新参数哈希版本 2 排序对象键、去除展示元数据并统一 Pi 原生工具路径/编辑字段；旧版本保留原 JSON 哈希规则。独立日志记录哈希版本。

历史 `Bash/Read` 结果哈希仅在完整原私有日志通过工作区、操作、任务、轮次、会话、调用 ID、参数及日志自身结果哈希校验，且能重现旧显示分类哈希时迁移；追加宿主审计。没有对应证据的历史错误不强行结清。未知终止回执有界重查，避免首次检查早于日志到达而永久不再检查。

## 验证

- `SuperAgentWorkerRecovery.test.ts`：所有 worker 替换、主要节点会话和任务板保留、无检查点/非持续工作接续、未知副作用局部阻塞、迟到回执、用户停止、清理预算跨重启、历史身份兼容。
- `fixtures/worker-recovery-crash.ts`：真实独立 Bun 进程修改文件并同步私有回执，然后在工具返回与模型完成前退出；新宿主核验回执并接续同一任务，重复原写入被操作身份去重拒绝。
- `SuperAgentOperationRecovery.test.ts`、`SuperAgentContinuity.test.ts`、`SuperAgentNodeRecovery.test.ts`：原证据、资源锁、截止时间、权限可见性、原核验与人工恢复回归。
- `SuperAgentService.test.ts`、`SuperAgentTopology.test.ts`、`SuperAgentScriptResults.test.ts`：恢复前后的通信链预算、旧拓扑迁移、队列满载、同一脚本结果复核及迟到完成事件。
- `SuperAgentWorkerRecovery.isolated.ts`：恢复按钮、同 ID 重试、阶段提示、用户停止和进行中禁用。

本恢复器沿用单宿主对同一状态目录的所有权约束。新增持久字段要求使用支持该字段的版本读取；保留部署前状态备份，不能把旧二进制读取失败当作损坏后清空文档。
