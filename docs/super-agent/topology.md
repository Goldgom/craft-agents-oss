# 三常驻节点架构

新建动态团队使用 roleTopologyVersion=2：用户 ↔ 主节点 coordinator ↔ 后台规划 planner ↔ 派工协调 orchestrator ↔ 其执行子节点 worker。

主节点接收原始需求、答复与显式配置修改。super_agent_submit_request 只带 requestId，宿主从当前用户轮取原文和附件引用，按原轮次去重。后台通过 requests 详情读取原文，以 sourceRequestId 维护需求契约，独占计划内容；协调节点独占模型选择、派工、依赖资源协调和执行证据验收。宿主创建 parentNodeId 并固定归属。派工须提交当前 planRevision 与 goalRevision；计划状态的宿主更新保留 contractRevision，后台重新发布才更新契约版本。

所有节点消息和现有会话消息均经宿主拓扑验证，持久队列恢复也重新校验。汇报只保存一份，宿主选择下一跳，按收件人独立固定批次和推进游标。管理节点需成功处理，主节点另需 deliver 才消费；失败批次和原文保留至恢复。sourceReportIds 引用本节点收到的证据，禁止通过重写把旧版本或未核验内容升级为已核验。共享板保存事实，不广播通知，也不用于绕过通信边界。

普通执行进度只唤醒协调节点；后台只处理新需求、计划问题与协调阶段结论，主节点只接收后台结论和提问。空确认、重复进度和完整历史不逐级转发。执行细节按引用查询，保留既有 Pi 最新快照投影与无损详情分页。

动态旧团队在主节点和协调节点当前轮结束、会话不再执行时迁移，可以保留仍在运行的执行子节点。先归档旧文档，保留主节点和协调节点 ID、模型、任务、检查点、产物、脚本和未知操作；后台默认继承原协调模型。赋予旧子节点父归属、迁移未读汇报和各收件游标，旧混合职责管理会话重新创建。迁移幂等，不重新执行任务或未知操作。固定旧团队沿用已有空闲归档重建流程。

停止、取消和全局权限弹窗由宿主直接处理。完全控制继续绕过应用权限限制，但保留角色拓扑、串行模型进程和用户选定环境。详见 permission-contract.md 与 context-contract.md。
