## 核心设计

- 每个工作区保存一个团队，新团队有一个意图主节点、一个编排节点和至少一个工作节点；旧团队空闲时升级。
- 每节点使用一个持久模型会话，节点内部串行，不同节点可以并行。
- 同一计划或阶段可拆成多个子任务，由多个工作节点使用相同 `planId` 协作执行。
- 意图主节点理解用户目标、交接意图和转交结果；编排节点维护计划、派工、依赖、资源与证据验收；工作节点执行和验证。
- 后台服务负责排队、限速、状态持久化、环境准备和工具权限检查。
- 从完整回复解析末尾单个动作块，独立限制显示文字和控制块，持久化实际动作回执。
- 脚本执行绑定运行、任务和计划；终态交编排节点处理，正常完成处理轮次后确认投递。
- 运行期间持续核对真实会话，丢失完成事件时结算未知结果并安排核验，保留原会话与产物供检查。
- 暂时网络、代理、服务和限流错误显示“恢复中”，保留原任务及会话，按递增间隔自动续跑；取消会终止恢复。
- 持续工作默认开启，在已有授权目标内推进计划；全队连续空闲达到可调的 `idleInspectionMinutes` 后触发后台自检，预设按用途选择 10～60 分钟。
- 任务 completed 表示提交结果；任务 acceptance 独立记录验收，现代计划完成要求所有关联任务已验收。

现已支持任务依赖、就绪释放、声明资源互斥和结构化验收引用。自动能力匹配、不可变产物版本与完整场景基准仍待实现。

维护时应同时更新设计说明和使用说明，并核对相关类型、校验规则及调度测试。
