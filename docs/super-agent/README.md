## 核心设计

- 每个工作区保存一个团队，新动态团队有主节点、后台规划、派工协调三个常驻节点，执行子节点按任务创建；旧动态团队在管理轮次结束后安全迁移。
- 每节点使用一个持久模型会话，节点内部串行，不同节点可以并行。
- 同一计划或阶段可拆成多个子任务，由多个工作节点使用相同 `planId` 协作执行。
- 主节点原样转交用户请求并答复；后台规划独占需求分析和计划；派工协调独占派工、依赖资源与任务验收；执行子节点完成任务。通信只允许相邻角色，子节点绑定自己的派工父节点。
- 后台服务负责排队、限速、状态持久化、环境准备和工具权限检查。
- 优先使用各角色注册工具并持久化回执；旧动作块仅为兼容入口，执行同样的角色、版本和通信校验。
- 脚本执行绑定运行、任务和计划；终态交编排节点处理，正常完成处理轮次后确认投递。
- 运行期间持续核对真实会话，丢失完成事件时结算未知结果并安排核验，保留原会话与产物供检查。
- 暂时网络、代理、服务和限流错误显示“恢复中”，保留原任务及会话，按递增间隔自动续跑；取消会终止恢复。
- 新动态团队持续工作默认关闭；启用后在已有授权目标内推进。普通执行进度只唤醒派工协调，阶段结论才逐级回流，避免空确认和重复上下文。
- 任务 completed 表示提交结果；任务 acceptance 独立记录验收，计划完成要求当前版本的成功任务与用户明确要求的复核证据。

现已支持任务依赖、就绪释放、声明资源互斥、能力标签匹配、结构化验收、产物哈希绑定和变更后的验收失效。自动兜底选人依据健康、负载与显式能力标签，不理解未声明的领域能力；产物登记没有冻结项目文件，完整场景基准仍需验证。

维护时应同时更新设计说明和使用说明，并核对相关类型、校验规则及调度测试。
