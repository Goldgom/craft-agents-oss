# 超级智能体重构实现说明

超级智能体入口现在采用两个常驻节点和动态执行池。底层复用已有普通智能体会话、工具、权限、模型连接、浏览器、Skills、凭据安全后端与自动化执行器。

创建流程分为“主节点 → 后台节点 → subagent 可用模型”。新建配置直接使用动态架构，不再先创建旧协作岗位或套用工作节点预设。模型池只表达可用模型、参数与能力；不要求设置 agent 的具体工作。能力描述、标签及评价合为“能力说明”，智能等级采用 0–100 分。旧星级按每星 20 分转换，旧说明合并且重复读取不会累加。每项派工由后台提供任务和思考强度，生成独立 subagent 与会话；同一模型可以并行用于多个任务，模型条目数量不限制执行实例数量。模型评价仅供选型，不注入工作偏好。Skills 和数据源通过工作区共享资源配置和任务资源分配管理，不在新模型表单中绑定。

## 已接入的行为

- subagent 模型设置采用紧凑卡片，常用项为连接、模型、0–100 分和能力说明，每项附作用说明。名称、执行后端、工作轮次限制及可选思考强度默认折叠。
- TokenNest 预设覆盖当前已认证连接、当前渠道分组实际可用的文本模型，包括 GPT、Claude、Gemini、DeepSeek、Kimi、Qwen、GLM 与 MiniMax 等模型系列；不添加账户无权调用的模型及图片、语音、视频、嵌入模型。新建时自动填充，已有模型池可一键补齐；相同连接和模型去重，不覆盖自定义配置，最多 100 条。预设分数与能力是可编辑的产品选型建议，不代表实测或官方基准成绩。
- 动态 subagent 结束后自动移出节点列表，不再提供编辑或重新分配任务入口；主节点与后台节点常驻。排队、等待、执行及恢复中的节点保留。内部执行身份、会话、工作记录与汇报继续保留，供验收、操作核验及历史追溯使用；它们不作为可复用协作成员展示。

- 默认使用执行者自检，不自动增加独立复核节点。验收条件本身不阻止已成功提交任务的下游启动，也不强制逐项登记验收后才能完成计划；只有用户明确要求独立复核时才使用对应任务标记与复核门槛。失败、过期、被拒绝或存在未确认操作的结果仍阻止下游及最终完成。空闲队列中已提交前置任务的阻碍会触发一次后台诊断，相同状态不反复唤醒。

- 主节点的对话页显示独立状态动画：等待、准备、思考、组织回复与恢复。排队状态由宿主提供，不依赖后台或 subagent 是否工作；完成、失败及等待用户授权时收起动画。仅显示状态，不展示内部思考内容，并支持减少动态效果。

- 用户可见的“受阻”仅指明确需要用户采取具体操作的情况。内部自动核验、恢复与依赖等待不显示受阻卡片、不计入受阻数量；计划显示处理中，任务显示等待。内部调度与结果核验约束仍保留，避免重复执行未知结果的外部操作。

- 交互节点提交、按版本修订及取消需求，可分页读取完整工作列表与汇报区。共享板、内部资料库、执行记录、文件、数据源和凭据操作由宿主权限拒绝。用户可直接操作配置界面，也可在主聊天明确要求修改配置：交互节点通过 `super_agent_settings` 读取版本并提交修改，本轮成功结束后保存；忙碌、版本冲突或中断时不会覆盖配置，凭据库访问开关仍只能在设置页修改。
- 后台节点可读取工作区共享资源与自动化元数据和超级智能体配置，由需求、共享板、执行进展和自动化事件唤醒，合并待处理事件，维护计划、选择模型、派工及验收。后台自身的写入不重复唤醒自己。
- 每项派工必须选择启用的模型条目并指定本次思考强度。模型目录支持统一能力说明、0–100 分、后端与工作轮次频率参数。保留旧数据中的资源绑定兼容字段。思考强度交给现有后端处理，最终有效级别受提供方模型能力限制。
- `maxConcurrentSubagents` 限制同时准备和执行的工作节点，不计算两个常驻节点。下调上限保留正在执行的任务，等待名额释放后再启动新任务。单次受限重试等待不占执行名额，但其独占资源仍按任务状态保护。
- 工作节点可直接提交阶段、成果、失败或问题汇报。汇报记录来源、需求版本、验证状态、产物 ID 及替代关系。未提交显式汇报时，宿主保存该工作轮的最终结果。
- 内置定时检查默认每 5 秒检查汇报，支持配置 1～3600 秒。每批最多处理 100 条，并根据内容长度限制上下文；超长单条汇报通过工具补读，成功交付或显式静默消费后才推进持久游标；批次启动后的新汇报留给下一批。失败保存恢复点，避免自动付费重试循环。未消费汇报不会被历史裁剪移除；积压超过容量时拒绝继续追加并提示先消费。
- 用户可在对话附加最多 10 个文件、总计 20 MB。宿主将内容保存到项目中的独立上传目录，交互节点只收到名称和路径引用，后台安排 subagent 解析内容。
- 左侧提供共享技能、数据源、凭据库、自动化与导入导出入口。普通智能体和超级智能体读取同一工作区资源；手动修改及 AI 工具写入对所有节点可见，实际使用仍遵守节点资源授权。
- `super_agent_resource_catalog` 查询共享元数据；后台和执行节点可使用 `super_agent_manage_resources` 修改数据源、凭据、自动化与导入资源，操作受权限检查和去重回执控制。凭据值不返回查询结果。
- 支持 JSON 配置导入导出，以及使用 scrypt 派生密钥、AES-256-GCM 加密的完整资源备份（包含凭据）。加密文件恢复时重映射为目标工作区凭据命名空间，错误密码拒绝导入。普通配置导出不包含凭据库密钥。
- 会话及数据源使用工作区原有目录，保存账户使用工作区 ID，数据源认证沿用工作区目录名命名空间。自动化由原有工作区调度器执行，避免重复扫描会话或创建重复调度器。

## 存储与迁移

协调状态继续保存在 `<workspace>/super-agent/commit.json` 和 `state.json`，包含工作列表、共享板、汇报、事件序列、消费游标和恢复点。

共享资源位于原有工作区目录。所有智能体共享资源目录和加密凭据库；节点使用权限继续由宿主策略控制。

旧团队空闲且没有待处理脚本结果时，宿主先将完整原状态归档到 `super-agent/history/legacy-*.json`，再转换为新配置。旧工作配置保留模型选择与基本参数转换为模型目录；岗位名称、岗位描述及工作偏好保留于归档，不转换为模型名称、能力描述或评价。旧执行状态不自动重放；保留聊天显示，等待用户继续。运行中的旧团队先完成或停止，再迁移。历史读取及旧格式兼容分支仍保留，生产入口对新配置使用动态架构。

## 验证与边界

新增自动化测试覆盖需求到汇报的完整宿主流程、指定模型与思考强度、并发上限、直接回调权限、未消费汇报保留、批次边界、重启游标、失败通知停止自动重试、附件内容隔离、取消与晚到结果、导入幂等、凭据隔离和真实脚本执行。

已完成共享包、服务端、桌面端、WebUI 的类型检查，以及桌面主进程、预加载和 renderer 构建。验收使用确定性模型宿主和本地脚本，没有使用真实模型账号或外部 MCP 服务；真实 OAuth 浏览器回调、外部数据源和长期定时任务仍需在实际连接环境验收。

额外会话回归中有两项既有测试要求“全权限仍限制工作目录、附件及数据源”，与当前底层“全权限跳过这些限制”的测试和实现相冲突。对仓库 HEAD 中原始策略的独立检查也确认该行为已存在。本次保留既有工作节点全权限语义；新交互和后台节点的角色边界仍由宿主独立限制。
