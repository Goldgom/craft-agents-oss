# 默认节点 Skills 与跨场景协作

现有日常、代码、科研、办公交付、故障运维五类预设均绑定默认 Skills，每类预设包含一个专门的 Computer Use 工作节点。节点沿用已授权模型选择和团队并发限制。

所有岗位均提供内置 `super-agent-collaboration` 的读取入口，通用规则在角色提示词中声明，详细协议按岗位参考文件读取。节点提示词仅包含技能名称、用途、路径及版本，不重复嵌入全部正文；详见 [上下文约定](./context-contract.md)。技能描述的操作遵循当前权限，内置技能本身及包内参考始终可读。

专业岗位优先承担对应工作；每套团队的辅助岗位补齐跨场景能力。编排节点每轮获得实际绑定技能的 `skillCatalog`（slug、名称、用途），结合模型、框架、权限和负载指定负责人。没有场景专岗时，将任务交给具备匹配 Skill 的辅助节点，并将复杂工作拆成可验证阶段。

## 岗位默认绑定

| 岗位 | 默认技能重点 |
| --- | --- |
| 意图主节点 | `intent-clarification`：目标、约束、澄清和结果转交 |
| 五类编排节点 | `task-orchestration`：按技能选人、依赖、资源和证据验收 |
| 桌面操作与界面验证（每个预设） | `windows-desktop-control`、浏览器自动化、软件验证和证据复核；使用标准模型观察并操作实际宿主桌面 |
| 日常执行 | 日常写作、学习、计划、浏览器检索、文档和结构化数据 |
| 开发 | 实现与调试、浏览器、来源接入、Pages；兼顾实验分析及故障定位 |
| 测试／代码审查 | 软件验证、证据复核和实际交互检查；审查岗另绑定开发方法 |
| 文献检索 | 网页与文献、浏览器、文档和来源证据 |
| 实验／科研复核 | 研究方法、软件或软件验证、数据和可视化、结论复核 |
| 资料分析／制作／质检 | 研究分析、数据、Office 文档、图表、Pages、绘画、桌面操作和证据复核，按岗位分配 |

完整绑定表维护在 `packages/shared/src/super-agent/default-skills.ts`，其中的 slug 都对应真实内置 `SKILL.md`。

## 每套团队的跨场景覆盖

| 场景 | 技能 | 默认辅助负责人 |
| --- | --- | --- |
| 日常事务、写作、翻译、学习、计划 | `everyday-assistance` | 协作执行；代码预设为代码辅助 |
| 开发、调试、脚本与集成 | `software-development`、`software-verification` | 优先专业开发／测试；其他预设由协作执行承接 |
| 研究、实验、定量及行业分析 | `research-methods`、`web-research`、`browser-automation` | 优先科研／分析；其他预设由资料整理承接 |
| 文档、表格、报告与数据 | `document-workflows`、`structured-data` | 资料整理；代码预设为检查执行 |
| 设计、绘画、主题与展示 | `canvas-editing`、`theme-package-design`、`pages-authoring`、`previews-and-diagrams` | 资料整理；代码预设为检查执行 |
| 服务故障与运维 | `incident-response`、`remote-operations` | 优先运维专岗；其他预设由协作执行承接 |
| 信息整理、长期知识与版本归档 | `knowledge-organization`、`evidence-review` | 资料整理；代码预设为检查执行 |
| 桌面操作、渠道交付与会话交接 | `windows-desktop-control`、`messaging-and-collaboration`、`session-workflows` | 协作执行；代码预设为代码辅助 |
| 数据源、技能、自动化、配置和可导入包 | 各类 authoring、`workspace-configuration`、`resource-transfer` | 协作执行；代码预设为代码辅助 |

“跨场景覆盖”表示有对应操作方法和负责人，不证明模型精通所有领域，也不创建缺失的工具或数据。Windows 桌面操作、浏览器、远程连接、图像模型及 MCP 仍依赖实际宿主、配置和授权。技能按本轮任务使用；不因为绑定了某项技能而运行全部流程。

协作节点不绑定 `llm-delegation` 或 `subagent-collaboration` 作为默认技能，团队继续由已有节点执行，不额外调用模型或派生子代理。`agent-authoring` 用于制作可导入的定义文件，不授权启动新节点。配置制作优先交付工作目录内的文件，不借此改写宿主凭据或团队权限。

## 生效与自定义

新建团队自动应用默认绑定。已有团队在“配置 → 团队”重新应用对应预设并保存后生效；无需删除历史任务。应用时补齐旧版预设的默认技能，保留自定义技能、数据源、后端、能力和脚本负责人。

每个预设的桌面操作专员绑定 `computerUse` 能力，宿主自动给它的任务加入 `host-desktop` 独占资源。操作前检查桌面状态、窗口和截图，操作后验证当前界面；其工作节点身份和自定义绑定在预设之间保留。实际桌面控制需要 Windows 交互桌面、完全控制且无容器执行器，技能不会绕过这些条件。

`defaultSkillSlugs` 记录上次应用的预设默认项，实际执行只看 `skillSlugs`。用户手动取消的默认技能不会在下一次应用预设时重新勾选；新增自定义技能会保留。仅拥有预设默认技能的旧岗位可在切换方案时被替换，不会因默认绑定形成不断增长的团队。

同 slug 的项目、工作区或全局 Skill 仍按现有优先级覆盖内置定义。编排看到当前解析定义的用途，执行节点收到该定义的实际内容。技能内容不能扩大文件、MCP、程序或浏览器权限。

## 自主启用与分发

编排和工作节点每轮获得 `resourceCatalog`：已安装 Skill 的名称与用途，以及团队授权源的类型、可用性和连接状态。未绑定技能只提供描述，选中后才传入真实指令；目录不包含凭据或 MCP 启动命令。

编排可给空闲工作节点增加绑定，同一块中的资源动作先于 `tasks` 执行：

```json
{
  "activateResources": [{
    "nodeId": "worker-id",
    "skillSlugs": ["software-verification"],
    "sourceSlugs": ["authorized-mcp-slug"],
    "reason": "验证任务需要该技能和已授权数据源"
  }],
  "tasks": [{"nodeId": "worker-id", "title": "验证结果", "instructions": "核对当前产物及来源证据"}]
}
```

工作节点也可自行选择资源，仅提交一个独立 `activateResources` 动作且 `nodeId` 为自己。宿主保持原任务未完成，自动续轮，在同一会话中更新技能指令、数据源工具和执行策略。续轮沿用通信预算、调用频率和并发限制，不重复已经完成的操作。存在未知操作结果或待处理脚本回执时先完成核验。

源必须在“资源 → 数据源”的团队授权池内，并已启用和完成所需认证。启用只增加节点绑定，不更改来源配置、团队授权池或审批模式；连接仍由会话工具加载流程建立，实际失败会显示，绑定成功不表示远端连接成功。资源绑定持久保存，并在“资源”页面显示。运行中、准备中或恢复中的其他节点不能被改资源；意图主节点继续只交接需求。
