# 聊天图片压缩与历史上下文

## 上下文压缩模型与失败恢复

在「AI 设置 → 对应连接的模型设置 → 上下文压缩模型」选择用于生成摘要的模型。该设置作用于 Pi 和 Codex 兼容后端的手动压缩、自动压缩与超限恢复。原生 Claude Code、原生 Codex 的压缩继续由各自运行时管理。

未指定模型，或指定模型不可用时，按当前连接列表的顺序尝试名称或 ID 含 `luna` 的模型，再尝试含 `haiku` 的模型，最后尝试列表末尾的文本模型。匹配不区分大小写，候选列表按模型 ID 去重；不会跨连接选择模型或使用另一连接的凭据。保存设置后，现有会话会刷新压缩配置。

摘要触及输出上限、为空或错误调用工具时，最多基于完整输入重新生成三次，逐步缩短摘要目标并增加输出余量。模型窗口较小时，对完整历史分段生成摘要后再合并，保留来源顺序。单次压缩最多六层分段合并、96 次模型请求；停止操作会中止后续请求。只有完整生成的摘要才会作为检查点保存；全部候选失败时保留原始会话并显示错误，不会将截断文本当作成功摘要。

主会话的摘要目标为 256–768 token，并以压缩前上下文的约 2% 扣除近期原文后作为参考预算；近期原文保留预算为 512 token。摘要仅保留当前任务、硬性约束、未完成事项和必要的精确引用，无关或已完成的工作不再逐次累积。预算是生成目标，不会通过硬截断丢弃完整摘要；若语义改写失败，保留已经完整生成的摘要。系统提示、工具定义和不可拆分的最新消息/工具调用仍会占用空间，因此总上下文不保证固定压缩率。

启用 TokenBird 记忆时，压缩前将被移出的文本历史、旧摘要与文件操作清单保存到会话目录的 `memory/compactions/*.md`，摘要附带由程序写入的读取路径。可用 `read` 或 `grep` 按需找回细节，重启后仍可读取。归档不截断工具文本，不复制图片二进制；原始会话及附件保持保留。归档成功后才省略 SDK 自动附加的完整文件清单。写入失败时保留该清单，且不会声称已保存记忆。关闭记忆或使用 native 模式时不写入这些归档；只有浏览器工具的受限节点继续使用其团队记忆流程。会话归档不自动作为全局偏好注入后续对话。

## 图片上传与历史图片

单张上传图片的上限为 2 MB（2 × 1024 × 1024 字节，按 Base64 编码前的文件大小计算）。超过上限的图片在客户端上传前自动压缩，服务端保存时再次校验；SFTP 上传在完成暂存后执行同样的校验。转换格式时同步更新 MIME、文件扩展名和发送给模型的图片数据。

“上传前压缩图像”设置控制额外的 100 KB 压缩目标。即使关闭该设置，2 MB 上限仍然生效。压缩保持长宽比，能通过 PNG 压缩达标时保留透明背景，需要 JPEG 时将透明区域铺为白色。无法解码或压缩的超限图片会阻止本次消息发送并保留草稿。

Pi 和 Codex 兼容后端会根据当前模型及 compact 预算调整发送给模型的历史图片：

- 保留最近两条用户消息里的上传图片，以及最近两条含图片的工具结果。
- 达到 compact 预算的 65%，或历史图片超过 4 MB / 8 张时，将更早的图片缩小到最长边 768 像素、约 96 KB 以内。
- 达到预算的 85%，或历史图片超过 8 MB / 16 张时，进一步缩小到 384 像素，并尝试把更早的图片替换为文字描述。
- 文字描述由当前支持视觉的模型生成，保留可辨识文字、数字、对象和布局，并标明不确定信息。每次上下文处理最多生成两份新描述，compact 最多生成三份；单次描述调用最多等待 20 秒，失败后一分钟内避免重复尝试。生成描述会产生模型调用费用。
- 描述失败时优先保留缩略图；已经耗尽 compact 预算时，使用带来源关联和缺失说明的文字记录。手动、自动和溢出恢复 compact 都会保留图片记录，已有描述会被复用。

历史图片降级只修改本次模型请求的上下文，原始附件和 SDK 历史记录保留。文字描述会省略部分细节，需要精确读取小字、尺寸或坐标时，应重新读取原图。原生 Claude 和原生 Codex 的历史 compact 仍由各自 SDK 管理；所有后端的上传路径均受 2 MB 上限约束。
