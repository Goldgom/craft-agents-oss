# 超级智能体

开发与维护设计见独立目录 [超级智能体设计文档](./super-agent/README.md)，包括架构、调度、状态、通信、持续工作与恢复规则。本文介绍配置和使用。

节点提示词要求按用户实际结果交付：制作 MCP、脚本或自动化时，用户要求的完整接口、调用方接入、运行与相关恢复属于交付范围；团队负责补齐自己尚未完成的实现，不把源码、模拟测试或健康检查当作功能可用。编排依据当前要求与实际证据安排剩余工作，交互节点只转述已验证范围。

持续任务的一次筛选结果使用阶段汇报；执行者须在活动任务中保存检查点、登记正式等待并回读，能否续做仍取决于实际调度配置与恢复次数。若旧任务已结束，先核对未决操作和排他交接，再由编排在同一目标、计划下分派剩余工作，消息不等同于恢复任务。定时提醒、运行及截止收工需有启用和执行验证，禁用排程或内部消息不构成部署。本段为模型工作要求，不改变权限、调度限制，也不保证模型始终遵从；相关测试核对提示词注入与正式等待恢复流程。

顶部新增「超级智能体」入口，与智能体、绘画、思维导图并列。配置与执行状态按工作区保存在 `super-agent/state.json`，同步提交副本 `super-agent/commit.json` 用于中断恢复；AI 密钥仍由原有提供商设置管理。

可以直接在主聊天中要求 AI 修改超级智能体配置，包括模型池、主节点与后台节点的模型、并发上限、汇报间隔和工作环境。主交互节点通过 `super_agent_settings` 先读取配置和版本，再提交修改；本轮成功结束后保存，系统消息确认保存结果。工作繁忙时需先在页面停止工作；中断或版本冲突不会覆盖原配置。后台节点只能读取配置，工作 subagent 不能修改配置；凭据库访问开关仍需用户在设置页调整，AI 不得自行提升权限来解除阻碍。

协作轮次由 Microsoft Agent Framework 路由并调用已有节点会话。执行宿主需要固定版本 Python 依赖，Windows 资源打包与执行服务器 Docker 已配置安装；其他宿主和开发环境见 [运行时说明](./super-agent/microsoft-agent-framework.md)。

对话、任务结果、实时活动和共享面板中的 Markdown 链接使用应用统一的打开流程：报告等支持的文件在应用内预览，网页使用系统浏览器，其他文件交给系统默认程序。Windows 绝对路径不受预览扩展名限制；`.pt` 等二进制 checkpoint 不提供文本预览，可右键选择「打开文件位置」或「复制地址」，未配置默认打开程序时使用文件位置访问产物。

## 首次设置

1. 设置助手名字和头像。
2. 建立一个意图主节点、一个编排节点和至少一个工作节点。选择日常助手、自主代码、自主科研、高效工作、故障运维方案，也可自定义；预设支持已有 AI 连接，只采用所选连接及账户当前分组可用的文本模型。
3. 为节点选择已有 AI 连接、模型、思考强度、评级、描述和工作偏好。最大工作速度限制每分钟启动的模型轮次，每个节点同时执行一轮，复用自己的持久会话。
4. 选择工作环境、文件目录和执行权限。

### 推荐预设

五类预设均为节点绑定对应默认 Skills，并由辅助岗位补齐跨场景能力。完整岗位与场景对应关系、生效方式和自定义规则见 [默认节点 Skills](./super-agent/default-skills.md)。

| 方案 | 节点组合 | 默认持续工作 | 默认空闲自检间隔 | 验收重点 |
| --- | --- | --- | --- | --- |
| 日常助手（新团队默认） | 意图 + 日常编排 + 日常执行 + 资料整理（Luna 协作） + 协作执行与核对（Luna 协作） | 开启 | 60 分钟 | 实际操作状态、当前事实、简洁可用的结果 |
| 自主代码 | 意图 + 工程编排 + 开发 + 测试 + 架构与疑难审查 + 代码辅助（Luna 协作） + 检查执行（Luna 协作） | 开启 | 10 分钟 | 同一版本的差异、构建、测试、未验证项 |
| 自主科研 | 意图 + 科研编排 + 文献检索 + 实验分析 + 方法复核 + 资料整理（Luna 协作） + 协作执行与核对（Luna 协作） | 开启 | 30 分钟 | 原始来源、基线、复现方法、不确定性、反证 |
| 高效工作 | 意图 + 交付编排 + 资料分析 + 文档制作 + 质量检查 + 资料整理（Luna 协作） + 协作执行与核对（Luna 协作） | 开启 | 15 分钟 | 受众与期限、事实与数字、文件可用性、实际交付 |

| 故障运维 | 意图 + 故障编排 + 诊断 + 修复 + 恢复验证 + 整理 + 辅助核对 | 关闭 | 10 分钟 | 原故障路径、恢复指标、变更记录与未验证项 |

预设集中定义在 `super-agent-presets.ts`，职责描述与工作方法分别进入节点配置。每套方案分离意图与编排，按领域配置执行节点：日常共 6 个节点，代码、科研、工作、运维各 7 个节点（含桌面操作专门节点）。默认并发任务上限分别为 2、3、4、3、2；所有预设默认执行者自检，不添加独立复核岗位。详见 [流程与验收设计](./super-agent/research-orchestration.md)。新增节点优先 `gpt-6-luna`，其次 `gpt-5.6-luna`，再选择可用的 Haiku / Flash / Mini / Nano / Luna，最后回退工作模型，不跨连接或分组。新增协作节点默认评级 2、思考强度 max，启动上限每分钟 6～8 轮；所有预设中实际选用 Luna 的节点（包括原有节点）均使用最高思考强度 max。其他原有节点保持原思考强度。模型名匹配和配置评级不代表能力测评或费用保证，最大工作速度不保证连接的总额度。

编排节点给协作节点明确输入、步骤、负责范围与验收条件。资料整理只做指定字段提取、分类去重和索引；协作执行辅助已有节点核对格式、附件、链接与来源对应关系；代码辅助只做定位与明确的机械修改；检查执行只运行指定命令并保留版本、退出码与日志。原制作、开发、测试、分析与审查节点继续负责各自工作，指定单一文件修改负责人，避免重复劳动与并发覆盖。输入冲突、复杂判断、核心逻辑与安全改动、统计分析或失败定位交编排节点协调专业节点处理。协作节点不会因失败自行扩大修改范围，检查通过也不能替代整体验收。

创建页与「设置 → 智能体节点」均提供五套方案，应用后可以编辑。现有团队更换方案时保留复用节点的 ID 和资源绑定；超出目标节点数但仍绑定数据源、能力或脚本的节点保留，避免资源失去负责人。环境、权限和注册资源保持原配置，模型与职责按方案更新。设置页保存后生效，修改节点或环境时需先停止工作，单独修改自检间隔可以在工作运行中保存。持续工作只在服务运行期间推进已授权目标，团队完全空闲达到所设间隔后自检，不会自行扩大目标。

分工遵循依赖与资源边界：独立准备可并行，同一文件指定单一修改负责人；真实实现产物就绪后再测试，关键成果按需独立审查。简单任务由执行者自检，专家无需处理所有任务。任务结果应包含产物路径或来源、实际验证证据、验证范围和阻碍；排队或任务轮次结束不能替代目标验收。

意图主节点处理用户对话与意图交接；编排节点维护计划、派工、巡检和验收；工作节点执行和验证。主节点和编排节点始终禁止工作工具。达到空闲自检间隔后，编排节点检查已有授权目标的进展。

主节点和所有工作节点默认统一使用 Execute（`allow-all`）执行模式，旧配置中的 Explore / Ask 会自动归一化。每次启动节点轮次时，会同步已有会话的模式和最新提示词，保留会话记录。环境能力开关与具体操作的权限申请独立于执行模式。

主节点只负责用户交互、理解需求、必要澄清和转交工作节点的结果。普通问答、研究分析、技术方案、读取资料、实际执行和验证均由工作节点完成；主节点根据用户目标与节点报告进行必要交接和状态记录，不自行执行或验证。缺少关键输入时再询问用户。

给工作节点的任务只包含目标、必要路径与授权范围、依赖、产物和验收条件。每轮附带精简的当前任务、实际权限、自己与主节点的通信地址，以及少量共享条目和近期相关消息；不重复任务正文，不附全队模型配置、无关计划或其他节点脚本。长历史、日志和共享条目使用带 `[…]` 标记的节选，条目 ID、版本和产物路径便于后续索取细节；完整任务及团队记录保留。提示词只在已分配脚本或当前任务涉及脚本时提供脚本协议。

## 首页与设置

### 自动压缩上下文

在「设置 → 工作环境 → 自动压缩上下文」启用或关闭自动压缩，设置触发阈值（8,000–2,000,000 token，默认 252,000），并选择压缩前是否保存检查点到 Memory（默认开启）。所有节点共用设置，按各自会话的上下文用量判断；累计输出 token 不计入阈值。修改配置前先停止工作。

达到阈值后，在节点下一轮开始前通过持久队列执行压缩，随后继续原来的待执行轮次，不中断正在运行的工具。暂时没有新轮次或没有取得上下文用量时不主动发起；模型自带的窗口保护仍可能提前压缩。重启保留排队压缩和用量去重标记，同一份用量不会重复触发。

压缩目标是保留约 10% 上下文，删除过时进度、重复说明和冗长工具输出，保留授权目标、未完成工作、精确路径、数值约定、阻碍和证据状态。Pi 后端同时缩短原文保留窗口，并在摘要过长时尝试一次语义重写；实际比例取决于模型输出及不可拆分的最近轮次，其他后端遵循各自的压缩实现。原始会话记录继续保留。

开启 Memory 选项后，自动或手动压缩会将相关任务、目标、计划、检查点和产物版本复制为可检索的恢复条目，同一会话更新同一条目。条目保留记录的状态和来源，不将模型报告标记为独立验证事实，不复制原始工具日志。条目有大小限制，恢复时应读取最新团队记录；Memory 库已满时继续压缩，原始团队记录不删除。稳定偏好、项目决策等长期知识仍由智能体通过 `super_agent_library` 主动整理。

### 预设切换、思考强度与执行条件

工作节点通过稳定的职责标识匹配，重排或改名不会把开发节点的资源转交给文献节点。职责匹配时保留 ID、资源和自定义能力标签；不匹配但仍绑定数据源、能力、脚本或自定义标签的旧工作节点保留原职责。意图与编排节点继续保留各自的交接身份。旧预设名称可识别时迁移；无法确定职责的资源负责人不按列表顺序替换。

节点设置提供建议思考强度与「采用建议强度」按钮：整理和指定命令检查建议 low，一般分析建议 medium，开发、实验与专业复核建议 high，困难任务再用 xhigh / max。既有默认强度保留。开启「允许按任务选择思考强度」后，编排节点或手动分配任务可设置 thinkingLevel；任务未设置则沿用节点默认，下一任务不会继承前一任务的覆盖值。后端按模型支持范围执行。

验收条件 acceptanceCriteria 描述交付要求，不自动开启强制复核。只有用户明确要求独立复核时，才设置 requiresIndependentReview=true 或启用工作流独立复核，并安排另一工作节点复核。手动派工提供逐行验收条件输入。

创建页及工作环境设置提供「执行条件检查」。代码默认声明 git，科研声明 python3 与浏览器，运维声明 sh；可按项目修改所需程序。无沙箱时检查宿主 PATH 中的程序文件，不执行程序；受限控制的实际命令需用户逐次批准。容器模式检查服务、本地镜像和所需程序，使用无项目挂载、只读且无网络的临时容器，不下载镜像；需预先准备工具链镜像与离线依赖。检查还核对工作目录与浏览器客户端。首次保存及执行条件变化时检查，工作节点启动前再次检查；短时间内共用结果。修改权限或关闭完全控制不被检查阻止。

检查通过表示声明的程序存在和当前连接可用；不证明项目依赖齐全、构建成功、外部账号可用或目标完成。环境改变后可手动重查。

### 运行统计

「设置 → 运行统计」展示模型轮次、工具调用、重试、续做、已结算执行时长、首次排队时长、保留任务的验收/失败数量及交付目标数量；节点表按节点与模型记录轮次、工具调用、失败/中断、时长、输出 token 与已记录模型费用。

节点和用量统计从功能启用后开始持久累计，旧历史不回填。每轮绑定会话累计输出和费用的起点，结束时只计增量，重试按实际执行轮次记录，重复完成事件不重复累计。输入 token 字段是当前上下文快照，不作为总消耗累加。缺少用量或费用显示「未取得数据」，零费用字段不证明免费；页面显示用量返回覆盖情况。费用可能不完整，不含外部工具消费，以供应商账单为准。任务数量基于仍保留的记录；清理历史后不能作为累计产出数量。

首页只显示主聊天和工作进度。节点、共享数据板、节点通讯、数据源、能力档案、脚本和环境配置集中在独立设置视图中。

主聊天只展示用户消息、必要的答复和授权卡，不展示主节点的思考、工具活动、内部接力或后台自检日志。主节点通过最终动作块中的 `userReply` 明确选择需要用户看到的回复；后台轮次未填写该字段时保持静默，不产生空白消息或“Completed”提示。已有普通自检消息也从聊天中隐藏。工作节点的真实文字、思考与工具活动仍在工作进度中查看，必要错误和权限请求保留。

向用户交付产物时，意图主节点可以同时填写 `userDelivery`，在主聊天中显示绿色底色的「阶段交互」或「最终交付」对话框。阶段交互用于阶段成果与围绕成果的具体问题，最终交付用于已确认完成的结果；普通答复保留原有样式。产物可点击打开，文件位置按钮使用当前超级智能体的工作目录；回复按钮将焦点移至聊天输入框，用户确认发送后才提交反馈。

```json
{"userReply":"报告初稿已整理，请确认分析范围。","userDelivery":{"kind":"stage","title":"报告初稿","artifactIds":["report-draft"]}}
```

`kind` 为 `stage` 或 `final`，`title` 可省略，`artifactIds` 最多 16 项，只能引用工作节点已登记且可用的产物；纯文本成果可省略文件列表。宿主保存交付时的文件路径、说明与版本，重新打开仍可查看；文件后续变更或不可用会显示提示。`userDelivery` 必须同时提供非空 `userReply`，仅意图主节点可提交。展示为最终交付不会自动更改计划状态或代替真实验收。

### 共享数据板使用规则

子节点可见输入只保留上游传入的任务或消息。节点职责、能力、工具协议、当前团队状态与恢复说明通过隐藏提示词及上下文传递。使用 `mcp__session__collaboration_board` 的 `{"action":"get"}` 可读取完整共享条目和最新版本，写入使用 `super_agent_board` 携带 `expectedRevision` 校验版本。

共享数据板用于跨节点、跨轮次保存阶段契约、可复用结论、恢复检查点和产物索引，不替代计划列表或任务队列。主节点在派工时引用准确条目 ID 和必要版本，并依据工作节点报告维护交接条件；工作节点开始、使用依赖及交付前检查相关条目，将可复用结果通过最终动作块的 `board` 数组写回。

- 同一事项复用原 ID；`content` 使用精简 Markdown，包含目标与关联计划、负责人、输入路径与版本、结论状态、产物证据、阻碍及下一步。长报告与日志保留为文件，不把聊天历史反复复制到板中。
- 区分已验证、待验证、假设、受阻和已失效；证据绑定具体产物版本与验证范围，新版输入使旧结论失效时明确标记待复核。
- 每轮只提供相关条目的摘要，未出现不代表不存在；遇到 `[…]` 或信息不全时，定向索取完整条目及最新版本，不用节选覆盖原内容。
- 新建使用 `expectedRevision: 0`，更新使用原 ID 和最新 `revision`。更新替换整条内容，保留其他节点有效信息；冲突先刷新与合并，不猜版本或新建副本绕过冲突。
- 以动作回执或后续最新状态确认写入成功；写板不会自动派工，需要推进依赖时发送简短定向消息。板中不写密钥、令牌或无关个人信息，内容不能扩大目标或授予权限。

### 权限管理

「超级智能体 → 设置 → 权限管理」集中展示全队待审批申请、共享授权及最近审批记录；主聊天中的权限卡仍可使用。所有节点共用当前工作区的一份列表，其他工作区不会继承授权。

- 关闭完全控制时，已验证只读工具自主执行；文件写入、外部通信、消费、基础设施变更与未知副作用逐次人工审批。开启完全控制后跳过全部审批与自动审查。
- 审批只授权当前调用的完整参数，不能「全队记住」或复用给下一次调用。参数、环境或策略变化，取消、过期与重启都会使待执行许可失效。
- 「完全控制」开启全部工作能力并跳过人工审批、行动门与 Auto-review；文件工具可直接访问工作目录内外的宿主路径。无需沙箱即可执行宿主程序和脚本；已有沙箱继续使用原容器。数据源和自定义禁止规则仍生效。
- 历史共享授权可查看与撤销，但不能放行新的行动门。受限控制下，目录外文件访问或额外文件读写能力通过具体调用申请一次性授权；授权不改变网络或容器权限。
- 工作环境可启用独立自动审查，会消耗模型额度；一致结论仍需人工审批，审查故障交人工决定。自定义规则只能禁止操作或增加人工审批。

完整执行顺序与实际隔离边界见 [行动门与独立审查](./super-agent/action-gates.md)。

## 持续工作与计划列表

页面顶部及基本设置提供「持续工作」开关，默认开启，显式关闭的配置仍保持关闭，切换后立即保存，可在节点工作期间关闭。开启后，编排节点主动维护和推进用户目标的未完成计划；所有节点、轮次队列及受管脚本连续空闲达到 `idleInspectionMinutes` 时，后台启动一次自检，根据已有团队记录检查待交接需求，并安排已有工作节点继续执行。间隔支持 1～1440 整数分钟，创建页及基本设置均可调整，持续工作开启时也可编辑；单独调整间隔后保存会重新计时，不中断现有任务。没有剩余工作或阻碍没有变化时保持静默，仅记录内部状态并重新计时；不会为保持忙碌而自行扩大用户目标。

持续工作下，已有可执行计划的后续任务在通信链达到限制时开启新阶段，验证仍由工作节点完成，编排节点依据报告验收，意图主节点转交结果；节点间消息继续遵守 6 跳、32 轮限制。计划或共享板版本冲突会在原通信链剩余预算内安排一次刷新与协调，保留并发修改，并核对先前已入队的任务，避免重复派工。连接失败或没有新回复的轮次报告失败，不复用上一轮回复及其中的动作。

运行中的节点、准备中的环境、排队任务、等待授权及运行中或状态未知的脚本均阻止空闲自检。后台调度由服务端运行，不依赖页面是否打开；退出程序或停止服务后不再计时，重启后从恢复时重新计算空闲时间。「停止全部工作」同时关闭持续工作，关闭开关本身保留已开始的工作。

「设置 → 计划列表」可添加、编辑和删除计划，工作进度中也有入口。每条计划保存目标和完成条件、优先级（1 最高）、待安排 / 推进中 / 受阻 / 已完成 / 已取消状态，以及进展与阻碍。计划随工作区保存，更新需匹配版本以避免覆盖。编排节点通过 `plans` 动作维护计划，通过任务的 `planId` 关联工作；未指定计划的任务自动创建关联计划。同一计划或阶段可拆成多个子任务，使用相同 `planId` 分派给多个工作节点，独立工作并行推进，同一节点内部仍按队列串行；已有具体子任务不重复分派。所有关联工作成功提交、明确要求的复核通过且相关脚本结果已处理后，编排节点依据实际结果标记计划完成；默认不要求额外复核或逐项验收记录。任一任务失败或停止会使计划受阻，其他节点成功不会自动解除该阻碍，需经检查后决定是否恢复。

## 历史信息清理

任务持续性与效率设置见 [检查点、等待与操作记录](./super-agent/continuity.md)。环境设置支持每个 AI 连接的并发和每分钟轮次上限、无进展提醒时间及自动续做次数；节点可声明能力标签，派工时按必需能力匹配。任务面板显示检查点、等待原因、未知操作及产物版本，失败或等待中的任务可从检查点继续。关闭应用保留未启动队列，有检查点且无未确认副作用的工作可在持续工作开启时自动恢复；显式停止会清除续做检查点。

「超级智能体 → 设置 → 历史信息清理」提供三种可选操作：

- **运行历史**：按 7 / 30 / 90 天或全部符合条件的历史筛选，预览可清理数量，可保留最近 0 / 20 / 50 条消息。清理前将移除内容保存到工作区的 `super-agent/history/` 归档文件；未完成或受阻计划、其关联任务与结果、原始用户目标和共享板保留。完整节点会话和项目文件保留。
- **模型上下文**：选择已有节点会话，通过原有 `/compact` 流程压缩上下文，保留目标、进展、路径引用及验证证据。此操作会调用模型；完整聊天记录保留。界面区分“已安排压缩”和实际完成，进度与结果可在节点会话中查看。
- **旧会话及附件**：按时间筛选当前工作区已结束或归档的会话，由用户逐项选择并确认永久删除。当前节点、未完成计划依赖、星标、协作和任务流程关联会话不列入候选。会话目录中的附件、下载及数据文件一并删除，项目目录不受影响；部分失败会分别报告。

以上操作在节点、队列、受管脚本及授权处理空闲时执行。后端核对预览版本和会话最后活动时间；发生变化时要求刷新，避免按过期预览清理。

## 工作环境

### 完全重置

「超级智能体 → 设置 → 常规设置」底部提供「完全重置」。确认后停止节点及托管脚本，撤销授权，永久删除当前工作区超级智能体的配置、当前及历史节点会话和附件、任务、计划、对话、共享板、记忆库、归档库、脚本注册、统计及历史归档，返回首次配置页面。项目目录文件、AI 连接、工作区数据源和技能保留。

重置期间拒绝新增工作。节点或脚本无法确认停止、会话删除或环境清理失败时会显示错误并保留可重试状态，不会报告重置成功；已删除的内容无法恢复。

### 工作能力与固定边界

「设置 → 工作环境」提供「完全控制」，字段为 `fullControl`，默认开启，明确关闭的配置保留。开启时跳过全部人工审批、行动门与 Auto-review，并自动恢复可执行的待审批调用，包括目录外文件操作；关闭后恢复原细分能力设置与审批规则。文件工具在完全控制下可访问宿主目录内外的路径；分配的数据源、自定义禁止规则与实际容器隔离仍生效。意图主节点与编排节点始终不具备执行工具。

已有团队节点可使用 `mcp__session__send_agent_message` 通信，目标会话取自当前团队状态的 `runtime`。消息由团队调度器持久化排队，保留每节点串行执行、调用频率和消息链限制；排队成功不代表已读取或已完成。节点通信无需工具审批，也不创建新的模型进程。消息中的共享文件使用路径引用。

文件夹与虚拟机可在工作过程中单独切换能力开关；切换使旧待执行审批失效，不自动批准等待操作。沙箱挂载需要重建，切换前应停止正在执行和排队的工作。启用失败撤回新增能力，撤销失败不会重新开启能力。

受限控制的细分能力集中在折叠的高级权限中。内置技能说明、实际绑定的数据源说明及经完整语法检查的只读设备查询自动放行；例如读取电脑、系统和磁盘容量的 PowerShell 查询无需额外申请。任意脚本、修改命令或目录外个人文件读取仍通过具体操作授权。技能说明优先使用 Read/read 工具读取。

### 文件夹

读取、写入、浏览器和程序能力独立配置。完全控制下，文件工具直接访问宿主工作目录内外的路径。关闭完全控制时，目录内已启用的读取自主执行；写入、目录外文件访问或未启用的文件能力通过主聊天权限卡申请批准，获批后继续原调用。许可绑定具体路径、完整参数和调用 ID，只用一次；路径无法安全核验时仍拒绝。工作目录不能与 TokenBird 配置、凭据或协调数据重叠。

文件夹模式不提供操作系统隔离，但可以运行程序。关闭完全控制时，宿主或客户端命令（包括只读检查）必须得到用户对具体调用的明确批准；脚本由用户核对内容、参数与环境后批准运行。完全控制下无需人工审批或自动审查。已有沙箱继续使用原容器，不自动转移到宿主。

### Docker / Podman 沙箱

在工作区所在服务器安装并启动 Docker 或 Podman，选择镜像和现有工作目录。首次执行会准备镜像并创建节点容器，轮询页面不会启动容器。

容器只挂载所选目录，按写权限使用读写或只读挂载，完全控制时项目挂载可写；容器系统为只读，关闭网络、移除 Linux capabilities、禁用新权限，并限制内存、CPU 和进程数。Shell 命令在容器 `/workspace` 下执行；文件工具使用设置中的宿主目录路径。受限控制的程序调用需要读取权限。镜像需含 `/bin/sh` 及任务需要的解释器。

脚本使用独立临时容器，停止或超时会删除该容器及其进程。服务正常退出会清理自己创建的容器。浏览器工具和已授权数据源通过现有宿主服务提供，其权限独立控制。

### 虚拟机

在已有虚拟机内运行 TokenBird 服务，并设置 `TOKENBIRD_EXECUTION_HOST=vm`。通过现有远程工作区功能连接该服务，在超级智能体中选择虚拟机模式和当前工作区 ID。工作在该虚拟机服务内执行；页面不会创建或启动虚拟机。

虚拟机内的文件权限遵循文件夹模式。需要通用 Shell 时，可申请具体命令授权，也可在该虚拟机内继续选择容器沙箱。

## 通信规则和共享数据

主节点始终只负责调度，因此它自身的文件、程序和浏览器权限为关闭，不代表工作节点不能执行。发给主节点的当前环境摘要分别提供 `nodePermissions`（本节点边界）和 `workerPermissions`（工作节点权限）；调度依据当前配置，不沿用旧聊天或共享板里的失效权限阻碍。

节点拥有稳定 ID，消息保存发送者、接收者、类型、时间及任务关联。每个节点有串行收件队列；主节点可分派任务，工作节点只能执行任务、向已有节点通信、提交结果和更新共享板。

工作节点收到团队消息后返回的新结果或错误也会通知主节点，不仅保存到历史。主节点据此处理依赖、后续安排和必要的用户回复，无需等到空闲自检；同一通信链已有待处理通知时复用该通知，避免重复唤醒。没有新内容的纯动作空回复不额外触发回调，通信预算、调用频率和停止规则仍生效。

节点使用内置 `super-agent-collaboration` Skill 与注册会话工具发起协作：`super_agent_intent`、`super_agent_dispatch`、`super_agent_plan`、`super_agent_accept`、`super_agent_message`、`super_agent_board`、`super_agent_resources`、`super_agent_deliver` 和 `super_agent_script`。工具直接提供参数 Schema，错误通过当前调用返回。每次调用使用本轮唯一 `requestId`，同参数重试复用持久回执。旧 `<super_agent_actions>` 仅保留历史兼容，同一轮不能与工具混用。未知字段、未知节点、工作节点创建任务、额外模型调用和子智能体派生均会被拒绝。消息链限制为六跳，并有每个用户请求的总轮次预算，避免节点互相回复导致无限运行。只有真实会话完成事件才会将任务标记完成；取消后的晚到事件不会恢复任务。

共享板条目使用递增版本号。模型修改必须提交读到的版本，冲突时保留已有内容并返回错误。用户界面同样携带版本进行更新。

## 网络恢复

模型调用正常结束却没有新的最终答复（含空白答复）时，节点同样显示「恢复中」，沿原任务和会话最多自动续跑 3 次。恢复前先核验已有工具结果、下载、脚本和训练进度，不从头重跑，不把旧回复当作本轮结果。空响应恢复次数会持久化，重启不会重置；连续恢复后仍无有效答复会显示失败并阻塞关联计划。停止任务或团队可取消待恢复轮次，已失败的历史任务不会被自动重新启动。

网络断开、请求超时、代理或服务暂时不可用、限流时，节点显示「恢复中」，保留原任务和会话，按 2、4、8、16、32 秒递增等待，之后每 60 秒自动继续。从首次故障起最多尝试恢复 10 分钟，到期不再发起自动重试，任务失败并阻塞关联计划；正在执行的请求不会因恢复时限到期而被强行打断。恢复截止时间持久化，重启不会重置。恢复会核对已有进度，不重新分派任务或重跑已完成脚本。停止任务或团队会终止对应恢复；关闭持续工作会停止等待恢复的后台自检。认证、余额和权限错误不会自动重试，仍需按错误提示处理。

首页「工作进展」及「设置 → 智能体节点」的异常节点均提供「刷新节点」，恢复中的节点提供「立即重试」，并显示下次尝试和截止时间。手动操作开启新的 10 分钟恢复窗口，继续原任务与现有会话，仍遵守节点调用频率限制，不跳过环境检查或权限审批。已取消、已完成任务不恢复；原结果不明或没有可用失败检查点时仅重置异常状态，不自动重跑。真正忙碌的节点不能刷新，受阻计划需由主节点检查后解除，避免掩盖其他失败子任务。

### 清除所有数据并保留配置

在「设置」底部点击「清除数据，保留配置」，确认后停止当前节点任务与托管脚本，删除当前工作区超级智能体的当前及历史节点会话、附件、对话、任务、计划、共享板、记忆库、档案库、授权记录、统计和运行历史。此操作不可撤销。

已保存的团队与节点、模型选择、技能和数据源绑定、执行环境与权限、持续工作设置及脚本注册完整保留；项目目录文件、AI 连接、凭据和工作区资源保留。清除后节点和脚本回到空闲状态，新任务使用全新会话，无需重新配置。持续工作仍按保留的设置运行。原有「完全重置」仍可用于同时删除配置并返回首次配置页面。

### 完全重置单个异常节点

在首页「工作进展」或「设置 → 智能体节点」中，异常节点提供「完全重置节点」。确认后删除该节点当前及历史会话和附件，清空待执行队列、失败检查点、审批记录、调用时间及错误状态，停止与该节点关联的托管脚本。尚未完成的任务停止，任务与结果记录保留供复查，不自动重跑；下次明确分配任务时创建新会话。

节点配置、共享板、记忆库、档案库、项目文件和其他节点的工作保留。真正忙碌的节点不能重置。若删除会话或停止脚本失败，节点保持异常且旧检查点不再重放，可再次执行完全重置；重置不会修复连接凭据、余额或提供商故障。

## 数据源、能力和脚本

数据源复用原有工作区数据源与凭据，并按节点授权。能力档案保存可复用指令，绑定到节点；也可导入已有工作区技能。

脚本管理器登记目录内文件、计算 SHA-256 并监测变更。节点登记不启动，文件变更不重启。关闭完全控制时，用户在脚本面板核对路径、参数与哈希后「批准并运行」，宿主校验版本与环境；开启时可直接「运行」，工作节点也可用 `super_agent_script` 的 `action=run` 与 `scriptId` 启动分配给自己的脚本。两种模式均使用入口脚本的只读副本在独立容器执行。支持 JavaScript、Python、PowerShell、Shell，镜像需有解释器。停止或超时清理脚本容器；状态未知时，复查旧进程前禁止再次启动。

## 会话与审批

关闭完全控制时，有副作用的操作、目录外文件访问和未启用的文件能力由行动门暂停并在主聊天显示权限卡。主节点说明操作与影响，用户决定是否批准；批准后继续原调用，拒绝、过期和停止结束等待。开启完全控制时跳过这些审批及独立自动审查，文件工具可直接访问目录外宿主路径。

审批绑定节点会话、调用 ID、工具、完整输入与环境，最多十分钟且只用一次；下一次相同操作也重新审批。改变命令、文件、参数、策略或执行环境使旧审批失效。`localbash` 与 `runshell` 不向超级智能体开放。

不符合结构规则的操作会报告真实原因。未分配数据源始终拒绝；已分配数据源仍需有效登录，关闭完全控制时还需行动门审批。完全控制不代替第三方登录。每个节点可通过「查看会话与审批」检查完整工具记录和登录请求。除文件夹或虚拟机能力开关单独切换外，配置变更需先停止执行和排队的工作。

当前受限节点支持 Claude 与共享工具检查链中的 Pi 兼容提供商。配置为 Codex 的受限节点使用 Pi 兼容后端执行，以确保所有工具经过同一权限检查链。

## 网页检索与读取

超级智能体节点统一使用 `browser_tool` 获取网页：`open` 打开浏览器，`navigate` 访问 HTTP/HTTPS 页面，`snapshot` 获取页面结构与内容，再按需滚动、点击和等待。完全控制可使用 `evaluate` 读取必要网页原文；受限控制遵循允许的浏览器命令及原操作授权流程。浏览器工具未启用或桌面客户端未连接时，节点报告具体阻碍。

Pi 和 Claude 节点不向模型提供原生 `WebFetch` / `WebSearch`，防止选中后被执行策略拒绝；普通智能体保留原网页工具。`browser_tool` 的长结果保存为文件与预览，由当前节点分段读取和总结，不额外调用摘要模型。
# 档案库与 Memory 库

在超级智能体管理侧栏打开“档案库”或“Memory 库”。两者按工作区保存，跨节点共享，重启、更换节点会话和清理运行历史后仍可使用；完整重置超级智能体会清除两库。

- **档案库**：为工程中间版本、报告或其他文件创建实际副本。填写工作目录内的文件或目录路径、版本说明和标签。每个版本记录文件清单与 SHA-256，源文件随后修改不影响已有副本。恢复到工作目录内尚不存在的新目录，父目录须已存在；恢复时逐文件核对哈希，不覆盖当前工程。支持二进制文件和空目录；不支持符号链接或 junction。上限为每文件 64 MB、每版本 256 MB / 2000 项、每工作区 100 个版本。大型工程宜先制作范围明确的版本包，避免复制依赖缓存与凭据。
- **Memory 库**：保存稳定偏好、已核实事实、项目决策、经验教训及来源。支持搜索、分类、标签、编辑和删除；最多 1000 条，每条内容 32000 字符。编辑使用条目版本号，冲突时需刷新后核对，不能覆盖其他节点的新记录。

智能体使用 `mcp__session__super_agent_library`：

```json
{"type":"library-list","library":"memory","query":"构建","limit":20,"offset":0}
{"type":"library-get","library":"memory","id":"memory-entry-id"}
{"type":"memory-upsert","item":{"title":"构建约定","content":"项目使用 Bun 构建。","category":"decision","tags":["工程"],"evidence":"package.json"},"expectedRevision":0}
{"type":"archive-create","item":{"title":"第一阶段版本","sourcePath":"project/src","versionLabel":"v1","description":"测试通过的阶段产物"}}
{"type":"archive-restore","id":"archive-entry-id","destination":"restored-v1"}
```

`library-list` 返回关键词检索摘要与匹配总数，`offset` 用于分页；`library-get` 返回完整内容或文件清单。每轮隐藏上下文带相关条目摘要，未出现的条目仍可通过工具检索。当前采用关键词匹配，不是向量或语义检索。

主节点与编排节点可读库索引和记忆，写入、归档和恢复交工作节点。归档需要文件读权限，恢复需要文件写权限；关闭完全控制时文件副作用经过原行动门。长期记忆不授予权限，不覆盖用户当前要求；不要记录凭据、令牌、整段聊天或未核实的猜测。

库索引和记忆随 `super-agent/commit.json`、`state.json` 持久保存；版本副本保存在工作区控制目录的 `super-agent/archive/<id>/`，工作节点通过专用工具访问。

## 对话中编辑设置

普通聊天和超级智能体交互主节点可使用 `super_agent_settings`。`action=get` 返回当前工作区的完整配置和 `revision`；`action=update` 提供读取到的 `expectedRevision` 与顶层 `changes`。未提供的顶层字段保留，嵌套对象和数组完整替换，因此应复制当前值后只修改用户指定的部分。名称、头像、节点与模型、运行框架、思考强度、技能与数据源、能力配置、调度与持续工作、工作环境与权限、安全规则、依赖程序和脚本注册均使用原有保存校验。版本号、凭据、运行记录和重置不属于设置编辑接口。

普通聊天在团队空闲时直接保存；主节点仅在自己的轮次是唯一待执行工作时提交待保存修改，成功结束该轮后再保存，并在下一轮读取确认。提交后不能继续派工。轮次中断、设置版本冲突或后端保存失败会取消修改并报告错误。待保存修改仅属于当前运行轮次，服务重启不会重放。忙碌团队应先通过已有页面停止工作。AI 仅按用户明确请求修改设置，不自行扩大权限。
