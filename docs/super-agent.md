# 超级智能体

开发与维护设计见独立目录 [超级智能体设计文档](./super-agent/README.md)，包括架构、调度、状态、通信、持续工作与恢复规则。本文介绍配置和使用。

顶部新增「超级智能体」入口，与智能体、绘画、思维导图并列。配置与执行状态按工作区保存在 `super-agent/state.json`，AI 密钥仍由原有提供商设置管理。

## 首次设置

1. 设置助手名字和头像。
2. 建立恰好一个主智能体和至少一个工作节点。TokenNest 登录后可选择均衡、快速、深入研究方案，也可自定义；预设只采用账户当前分组可用的文本模型。
3. 为节点选择已有 AI 连接、模型、思考强度、评级、描述和工作偏好。最大工作速度限制每分钟启动的模型轮次，每个节点同时执行一轮，复用自己的持久会话。
4. 选择工作环境、文件目录和执行权限。

主节点处理用户对话、安排工作、巡检和汇总，具体工作分给工作节点。受限控制时主节点禁用文件写入与程序执行；完全控制时具备全部工具权限，仍优先分派主要工作。工作完成会汇总给主节点。达到设定空闲时间且有待检查活动时，主节点检查节点、任务和脚本状态。

主节点和所有工作节点默认统一使用 Execute（`allow-all`）执行模式，旧配置中的 Explore / Ask 会自动归一化。每次启动节点轮次时，会同步已有会话的模式和最新提示词，保留会话记录。环境能力开关与具体操作的权限申请独立于执行模式。

主节点收到操作请求后，会主动分派真实任务并根据工具结果推进和汇报。例如清理磁盘先安排节点检查实际空间和缓存；权限不足时说明具体申请，等待权限卡处理。任务排队、开始和完成分别汇报，避免把建议、计划或尚未验证的操作当作执行结果。

给工作节点的任务只包含目标、必要路径与授权范围、依赖、产物和验收条件。每轮附带精简的当前任务、实际权限、自己与主节点的通信地址，以及少量共享条目和近期相关消息；不重复任务正文，不附全队模型配置、无关计划或其他节点脚本。长历史、日志和共享条目使用带 `[…]` 标记的节选，条目 ID、版本和产物路径便于后续索取细节；完整任务及团队记录保留。提示词只在已分配脚本或当前任务涉及脚本时提供脚本协议。

## 首页与设置

首页只显示主聊天和工作进度。节点、共享数据板、节点通讯、数据源、能力档案、脚本和环境配置集中在独立设置视图中。

聊天和进度通过真实会话事件实时更新，显示提供商输出的思考摘要、回复文字、工具执行和等待授权状态。提供商没有输出思考内容时，显示实际文字和工具状态。页面还会定期刷新快照以恢复断开的事件更新；内部调度指令不会出现在主聊天中。

## 持续工作与计划列表

页面顶部及基本设置提供「持续工作」开关，默认关闭，切换后立即保存，可在节点工作期间关闭。开启后，主智能体主动维护和推进用户目标的未完成计划；所有节点、轮次队列及受管脚本连续空闲 30 分钟时，后台启动一次自检，反思遗漏与后续步骤，并安排已有工作节点继续执行。没有剩余工作时记录自检结论，重新计时；不会为保持忙碌而自行扩大用户目标。

持续工作下，已有可执行计划的后续任务在通信链达到限制时开启新阶段，工作节点的结果仍交给主节点核验；节点间消息继续遵守 6 跳、32 轮限制。计划或共享板版本冲突会在原通信链剩余预算内安排一次刷新与协调，保留并发修改，并核对先前已入队的任务，避免重复派工。连接失败或没有新回复的轮次报告失败，不复用上一轮回复及其中的动作。

运行中的节点、准备中的环境、排队任务、等待授权及运行中或状态未知的脚本均阻止空闲自检。后台调度由服务端运行，不依赖页面是否打开；退出程序或停止服务后不再计时，重启后从恢复时重新计算空闲时间。「停止全部工作」同时关闭持续工作，关闭开关本身保留已开始的工作。

「设置 → 计划列表」可添加、编辑和删除计划，工作进度中也有入口。每条计划保存目标和完成条件、优先级（1 最高）、待安排 / 推进中 / 受阻 / 已完成 / 已取消状态，以及进展与阻碍。计划随工作区保存，更新需匹配版本以避免覆盖。主节点通过 `plans` 动作维护计划，通过任务的 `planId` 关联工作；未指定计划的任务自动创建关联计划，同一计划已有排队或运行任务时禁止再次分派。工作节点提交结果后，主节点核验目标完成情况，再标记计划完成；失败或停止的任务使关联计划受阻，避免未经检查直接重试。

## 历史信息清理

「超级智能体 → 设置 → 历史信息清理」提供三种可选操作：

- **运行历史**：按 7 / 30 / 90 天或全部符合条件的历史筛选，预览可清理数量，可保留最近 0 / 20 / 50 条消息。清理前将移除内容保存到工作区的 `super-agent/history/` 归档文件；未完成或受阻计划、其关联任务与结果、原始用户目标和共享板保留。完整节点会话和项目文件保留。
- **模型上下文**：选择已有节点会话，通过原有 `/compact` 流程压缩上下文，保留目标、进展、路径引用及验证证据。此操作会调用模型；完整聊天记录保留。界面区分“已安排压缩”和实际完成，进度与结果可在节点会话中查看。
- **旧会话及附件**：按时间筛选当前工作区已结束或归档的会话，由用户逐项选择并确认永久删除。当前节点、未完成计划依赖、星标、协作和任务流程关联会话不列入候选。会话目录中的附件、下载及数据文件一并删除，项目目录不受影响；部分失败会分别报告。

以上操作在节点、队列、受管脚本及授权处理空闲时执行。后端核对预览版本和会话最后活动时间；发生变化时要求刷新，避免按过期预览清理。

## 工作环境

### 完全控制

「设置 → 工作环境」提供完全控制开关，默认开启。未保存该字段的配置同样默认开启，明确关闭的设置保留。开启后，主节点和全部工作节点直接读写文件、运行程序、操作浏览器和使用已配置的数据源，无需逐次申请工具权限，也可访问工作目录之外的位置。细分能力开关收起，关闭完全控制后恢复原设置。操作使用实际连接宿主机、客户端或虚拟机的账号；所选执行环境的真实隔离及登录状态仍生效。

已有团队节点可使用 `mcp__session__send_agent_message` 通信，目标会话取自当前团队状态的 `runtime`。消息由团队调度器持久化排队，保留每节点串行执行、调用频率和消息链限制；排队成功不代表已读取或已完成。节点通信无需工具审批，也不创建新的模型进程。消息中的共享文件使用路径引用。

文件夹与虚拟机可在工作过程中仅切换完全控制：开启后继续原先等待授权的调用，关闭后立即撤销当前和历史隐藏节点会话的全权访问。沙箱挂载需要重建，切换前应停止正在执行和排队的工作。启用失败会撤回新增的全权访问，撤销失败不会重新开启全权。

受限控制的细分能力集中在折叠的高级权限中。内置技能说明、实际绑定的数据源说明及经完整语法检查的只读设备查询自动放行；例如读取电脑、系统和磁盘容量的 PowerShell 查询无需额外申请。任意脚本、修改命令或目录外个人文件读取仍通过具体操作授权。技能说明优先使用 Read/read 工具读取。

### 文件夹

受限控制下，文件工具会校验目录边界、符号链接和 Windows junction。读取、写入、浏览器和程序能力独立配置，主节点和工作节点统一使用 Execute；需要额外能力或范围时，通过主聊天申请具体操作授权。完全控制下，文件与宿主程序直接使用，无目录范围审批。

文件夹模式不提供操作系统隔离。通用 Shell 默认受限，工作节点需要通过主聊天申请具体命令的临时授权。授权卡显示完整命令、工作目录、执行机器和有效范围。已登记脚本可由用户手动运行；因为宿主程序能够访问整台机器，需要明确授予全部环境能力。模型无法用登记脚本绕过通用程序限制。

### Docker / Podman 沙箱

在工作区所在服务器安装并启动 Docker 或 Podman，选择镜像和现有工作目录。首次执行会准备镜像并创建节点容器，轮询页面不会启动容器。

容器只挂载所选目录，按写权限使用读写或只读挂载，完全控制时项目挂载可写；容器系统为只读，关闭网络、移除 Linux capabilities、禁用新权限，并限制内存、CPU 和进程数。Shell 命令在容器 `/workspace` 下执行；文件工具使用设置中的宿主目录路径。受限控制的程序调用需要读取权限。镜像需含 `/bin/sh` 及任务需要的解释器。

脚本使用独立临时容器，停止或超时会删除该容器及其进程。服务正常退出会清理自己创建的容器。浏览器工具和已授权数据源通过现有宿主服务提供，其权限独立控制。

### 虚拟机

在已有虚拟机内运行 TokenBird 服务，并设置 `TOKENBIRD_EXECUTION_HOST=vm`。通过现有远程工作区功能连接该服务，在超级智能体中选择虚拟机模式和当前工作区 ID。工作在该虚拟机服务内执行；页面不会创建或启动虚拟机。

虚拟机内的文件权限遵循文件夹模式。需要通用 Shell 时，可申请具体命令授权，也可在该虚拟机内继续选择容器沙箱。

## 通信规则和共享数据

节点拥有稳定 ID，消息保存发送者、接收者、类型、时间及任务关联。每个节点有串行收件队列；主节点可分派任务，工作节点只能执行任务、向已有节点通信、提交结果和更新共享板。

模型输出通过 `<super_agent_actions>` 中的严格 JSON 发起操作。未知字段、未知节点、工作节点创建任务、额外模型调用和子智能体派生均会被拒绝。消息链限制为六跳，并有每个用户请求的总轮次预算，避免节点互相回复导致无限运行。只有真实会话完成事件才会将任务标记完成；取消后的晚到事件不会恢复任务。

共享板条目使用递增版本号。模型修改必须提交读到的版本，冲突时保留已有内容并返回错误。用户界面同样携带版本进行更新。

## 数据源、能力和脚本

数据源复用原有工作区数据源与凭据，并按节点授权。能力档案保存可复用指令，绑定到节点；也可导入已有工作区技能。

脚本管理器登记文件，计算 SHA-256 并监测变更。完全控制时，文件夹或虚拟机允许目录外脚本，工作节点可直接运行分配给自己的登记脚本；沙箱脚本需在挂载项目内。变更和运行状态同步给节点，修改文件不会自动重启程序。支持 JavaScript、Python、PowerShell、Shell；解释器必须存在于所选执行环境中。正常停止会终止进程树。服务异常退出后无法确认的宿主脚本显示「进程状态待确认」，复查旧进程前禁止再次启动。

## 会话与审批

受限控制时，节点缺少文件、程序或浏览器权限，原工具调用等待授权，向主节点发送申请并在主聊天中显示权限卡。主节点负责说明申请和工作状态，用户决定是否授权。允许后原调用继续执行，保留节点原来的串行工作顺序；拒绝、过期和停止都会结束等待。完全控制直接执行工具，并自动继续已有的可用操作申请。

临时授权绑定节点会话、具体工具、完整输入和实际执行目标，仅在当前工作轮次内有效，最长十分钟。授权不会扩大整个工作目录；改变命令、文件、参数或执行机器需要重新申请。`localbash` 的客户端目标会在申请时锁定，客户端断开后不会换到另一台机器执行。

不符合结构规则的操作（例如增加模型进程或不支持的工具）仍会向主节点和主聊天报告原因，由主节点建议配置调整。未分配的数据源在受限控制时要求绑定，完全控制可使用实际可用的数据源；登录凭据仍须有效。每个节点可通过「查看会话与审批」检查完整工具记录和处理数据源登录请求。除文件夹或虚拟机的完全控制单独切换外，配置变更需要先停止正在执行和排队的工作。

当前受限节点支持 Claude 与共享工具检查链中的 Pi 兼容提供商。配置为 Codex 的受限节点使用 Pi 兼容后端执行，以确保所有工具经过同一权限检查链。
